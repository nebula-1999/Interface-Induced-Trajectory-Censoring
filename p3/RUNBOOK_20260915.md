## 已落地的保护

- 正式配置默认 `STEPS=150 / EVAL_FREQ=30 / SAVE_FREQ=30 / KEEP_CKPT=2`，
  保存/评测频率必须为正，终点必须同时落在两种周期上。
- 默认实际入口是 **1-step smoke**，step 0/1 都评测，step 1 保存；评测默认4题。
  最多允许2步，保持原有正式训练 batch/n/长度，检查正式形状的资源压力。
- `RUN_ID` 必填；目录是 `P3_RUN_BASE/RUN_ID/ARM`，默认在数据盘。
  目录已存在即拒绝。不再递归删除 checkpoint/event，不再清理全局工具标记。
- Ray 临时目录使用数据盘短路径 `P3_RAY_BASE/<RUN_ID/ARM哈希>`，映射写入
  `launch.json`，并在启动前检查长度；
  这是为了同时避开系统盘空间和 AF_UNIX 107字节 socket 上限。
- 两臂用同一 `RUN_ID`，但各自独立 outputs；父目录保存共同的训练/评测 manifest。
  训练清单比较最终 Hydra 参数（后值覆盖前值）、数据/关键源码哈希、软件版本；
  排除 parser 干预和两个记账字段。还要求 pytest 在训练解释器环境中可识别。
  模型 config/tokenizer_config 被记录；这**不等于**全部模型权重已验证一致。
- 评测清单绑定实际 EvalPlus/probe 内容、提示词、温度、长度与协议；不能悄悄换题。
- step 使用唯一身份，只能写一次；缺题、重复题、repair缺失、请求错误均不能完成。
  任一必需评测异常中止训练，不因前面成功过就继续。
- 新产物 `step_NNNNN.jsonl` 附 run_id/step/channel/task_id 与 manifest 哈希；
  `.complete.json` 保存行数和文件哈希。`.started` 无 `.complete`，或者 `.failed`
  均不能纳入学习曲线。新重试必须另建 RUN_ID，不能手删 marker 再拼接。
- smoke 结束后还检查预期评测点和末步 actor checkpoint 非空；这个结果只表示
  产物存在且基本完整，**不证明 checkpoint 可加载**。正式验收永远不会由它自动通过。
- 新 parser 辅助重放标记 `diagnostic_version=2`；修正单捕获组返回字符串的问题。
  旧诊断数据不覆盖、不静默重新分类。tight 仍是启发式，不自动升级为合法调用。

## 不用 GPU 的本地检查

在仓库根目录：

```bash
python3 -m unittest test_p3_acceptance -v
bash -n p3/run_p3_arm.sh p3/run_p3_probe.sh
ARM=broken RUN_ID=acceptance-preview P3_MODE=formal DRY=1 \
  P3_PYTHON="$(command -v python3)" bash p3/run_p3_arm.sh
```

Dry-run 不创建目录、不导入 verl、不修改兼容补丁、不清理文件、不启动 GPU。
打印的完整 Hydra 命令中，探针默认值在前、臂覆盖值在后；以最终生效参数为准。

## 服务器可连接后的执行顺序（本次尚未执行）

1. 核对新机器的连接信息、实际部署源码哈希、依赖、GPU及磁盘。
   先用同一解释器执行 sandbox/pytest 正反例。历史“15GB”不可作为现盘余量证明。
2. 检查 `DRY=1` 输出。确认两臂仅 parser 干预不同、评测接口相同。
3. 各跑一条独立 smoke，例：

   ```bash
   ARM=broken RUN_ID=acceptance-20260915-a P3_MODE=smoke \
     P3_PYTHON=/root/code-venv/bin/python bash p3/run_p3_arm.sh
   ARM=repaired RUN_ID=acceptance-20260915-a P3_MODE=smoke \
     P3_PYTHON=/root/code-venv/bin/python bash p3/run_p3_arm.sh
   ```

   示例只说明接口，不表示此日期的 RUN_ID 可复用或机器已经准备好。
   任何失败都保留原目录；同一配对试验若改代码/数据/配置，另起共同 RUN_ID。
4. 验证 step 0 与 step 1 的评测请求究竟路由到哪份模型/LoRA。
   记录权重版本、adapter路由和同步完成的证据；生成文本变化不是充分证据。
5. 量 checkpoint 实际占用，核对 actor/optimizer及训练恢复状态。
   根据服务器实际 verl 版本实现并验收显式 checkpoint 恢复，证明 global step
   从1继续到2、而不是重启；恢复的新事件/评测目录必须隔离。
   `resume-smoke` 会在启动前记录源 checkpoint 每个文件的大小与 SHA-256，
   然后把 step1→step2 写入新的 RUN_ID；绝不覆盖源目录。
6. 实测工具返回 observation 和下次生成输入的对应关系，补可联结标识。
7. 两臂均通过后，才解除代码中的正式运行门控。根据实际峰值和保留策略留磁盘余量；
   不能仅用 checkpoint 文件存在或训练 rc=0 替代验收。

旧 `watch_p3.sh`/自动接力配置不应直接复用：缺少 RUN_ID 的调用现在会拒绝。
本轮没有修改或创建自动化，也没有替用户启动或关闭机器。
