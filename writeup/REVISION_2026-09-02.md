## 一、收束后的结构

核心命题只有一句，全部实验都必须挂在它上面：

> **服务接口同时是测量函数的一部分和智能体有效动作空间的一部分。当模型—序列化—解析器
> 这份契约不匹配时，行为会在 benchmark 打分或 RL 反馈观察到它之前就消失。**

## 二、模拟审稿（ICLR/NeurIPS/ACL 主会口径，对象为 2026-09-02 稿）

### Summary

论文主张服务层的工具调用接口同时参与测量与动作空间，接口契约不匹配会让模型行为在
被打分或被强化之前消失。证据包括四家族的分层失败、Qwen2.5-Coder 的族内规模曲线
（服务端解析恒 0 而合规发出升至 80/100）、同血统 Instruct 对照（1→88）、离线重放
矩阵、Llama 的单变量 `strict:true` 干预（23%→0）、BFCL v4 上的复现（同权重同题同
评分器，0.00→0.96 / 0.00→0.19），以及 RL 侧的仪表化（执行 0 次而 reward 仍上升）。

### Strengths

1. **BFCL 复现把测量效度问题从自建 harness 移到了公共基准上。** 这是全稿最强的
   外部效度证据，且用的是官方数据、执行器、评分器与 pinned commit。
2. **Llama 的 `strict:true` 干预是干净的单变量因果**，且它推翻了作者自己此前三次
   对照得出的"模型缺陷"结论——这种自我推翻在论文里被显式保留，可信度很高。
3. **失败层分解是可证伪的。** 作者逐行重放服务端解析器，得出"真 parser 损失全库
   0 例"，并据此**收紧了自己论文标题词的定义**。主动缩小结论范围的论文很少见。
4. **仪表化与 errata 的透明度远高于同类。** 7 个 provenance 记错的臂、5 个不可比
   的臂、1 个作废的 p 值全部列出；人工校准链 0.950→0.975→0.900 完整保留。
5. **可操作产物**：98 行 preflight 能抓住文中全部静默失败。

### Weaknesses

1. **"Censoring" 这个词与 §5.2 自己的结论存在张力。** 作者证明真 parser 损失为 0：
   Coder 根本不产 `<tool_call>` 包装层，Instruct 产了但载荷非法。那么"接口审查了
   行为"与"模型没按契约输出"之间的界线，取决于把契约的哪一侧算作"接口"。论文已
   把定义收紧到"尝试从未以 parser 可接受的形式抵达"，但**标题与部分正文仍在用一个
   听起来像"解析器有 bug"的词**。这不是措辞洁癖：它决定了读者认为该修的是模型
   还是服务栈。建议在 §1 用一段正面处理，而不是留在 §5.2 的分解里。
2. **BFCL 的 0→196 仍是 adapter 级归因。**（作者已诚实标注，并给出 2×2 设计。）
   在补上之前，"benchmark 分数跨越整个 metric range"这个 headline 的因果主语是
   "一整套 adapter 配置"，比"一个 parser 标志"弱。
3. **RL 部分的链条在 1.5B 上是断的。** 作者自己的探针显示该条件下 52/100 的
   call-shaped 输出中 0/52 命中 `run_tests`——即策略发出的是语义错误的动作，不是
   合规动作被审查。论文现已只声称"经验分布中不存在工具轨迹"，这是对的；但摘要与
   标题仍容易让人读成后者。**7B 的 rollout 探针是唯一能闭合这条链的实验。**
4. **Instruct 梯子的执行层作废（宿主未装 pytest）。** 作者披露充分，并用离线重放
   精确补回首轮通过率。但审稿人会问：一个五臂实验在跑之前没有验证执行器，
   同类错误是否影响了其他臂？（论文应正面回答：其他臂的 pass 非零，执行器可用。）
5. **抽样仍是 `clean[:100]` 而非随机**，且多数臂单 seed。作者已列为局限并有脚本，
   但未跑。这条对"数值大小"的威胁大于对"方向"的威胁。
6. **修复后的 BFCL multi_turn 只有 0.19。** 若 adapter 本身也不完美，则 0→19 是
   接口效应的**下界**——这其实对论文有利，但现稿没有把它说成下界。

### Questions

1. 如果 2×2 消融显示 0→196 主要由 **chat template** 而非 parser 驱动，论文的核心
   命题需要改写吗？（我认为不需要，但作者应预先说明为什么。）
2. §5.2 的失败层分解显示 Instruct-3B 有 26 例"载荷合法、仅因尾部残留被
   `json.loads` 拒绝"。这是**唯一**一处严格度真的造成损失。为何不把它提升为一个
   独立的、可修的工程建议（用 `raw_decode`）？
3. 四家族中 Mistral"没有任何可接受的 100 题对照"。这是否意味着分类学的第四层
   实际上只有三个实例支撑？
4. 98 行 preflight 是否也能检出 §5.2 中"包装层缺失"这一类（而不只是 400/404）？

### Overall score / Confidence

**6/10（Weak Accept），confidence 4/5。**

分数卡在 6 而不是 7 的原因只有两个，且都已被作者自己点名：**BFCL 的 adapter 级
归因**，与 **RL 链条在 1.5B 上的断裂**。这两条不是写作问题，是证据问题。

### 什么能把 6 推到稳的 7

按 ROI 排序：

1. **7B verl rollout 探针**（最高）。若得到 emitted>0 / accepted=0 / executed=0，
   RL 那一节从"分布性缺失"升级为完整因果链，标题里的 RL 主张才真正成立。
   不需要完整训练。
2. **BFCL 2×2 消融**。两次额外 vLLM 启动。它把全稿最强的外部效度证据从 adapter
   级提升到可分解级。
3. **P0：随机 n=300**。它同时消掉"非随机抽样"和"功效不足"两条，且脚本就绪。
   它不提升因果强度，但消掉两条最容易被抓的方法学质疑。

**不建议**：换第四个家族、扩协议矩阵、加更多模型。它们不封堵任何已点名的缺口。
