# 1.5B code agent 的多轮能力：三层否定，以及 RL 为何修不好它

> **一句话**：Qwen2.5-Coder-1.5B **有**工具调用能力（强制时 8/8 格式全对）、**有**
> 修复能力（给定单点错误能修好 61%），但它**从不自主发起多轮**——任何 prompt 措辞
> 下主动调用率都是 0，强制调用一次并喂回失败反馈后也 0/6 重试。即使由外部强制驱动
> 多轮，540 题中靠多轮救回的也只有 8–9 题，且 **150 步 GRPO 完全不改变这个数字**
> （三个独立 run 一致）。

**规模**：单卡 A800，Qwen2.5-Coder-1.5B-Instruct，150 步 GRPO ×2 seed + RLOO ×1；
主动性诊断覆盖 1.5B/3B/7B/14B/32B 五档，
评测集 **540 题**（HumanEval+ 164 + MBPP+ 378，**排除 2 条已确认的 EvalPlus
数据缺陷** `HumanEval/32`、`Mbpp/599`——官方参考解都过不了）。主动性诊断另用
5 个规模 × 200 道真实训练题。
GPU 总花费约 ¥110。

**与已有工作的关系**：小模型工具调用失败本身已有报道（ToolFailBench、Llama-3B
benchmark、MAST），GRPO 在多轮 agent 上不稳定亦有记载（RAGEN 报告 Sokoban 上
10 步开始崩溃；GTPO 通过 turn-level reward 改善工具正确率约 3%）。**本文不主张
这些结论的首发权**，贡献在于：三层缺陷的分层量化、增益归因的分解方法，以及
**公开全部 per-task per-turn 轨迹**——据我们检索，该方向尚无公开此类数据的工作。

---

## 1. 三层否定

### 第一层：不会主动调用工具（`tool_choice=auto`）

**五个规模、每格 200 道真实训练题**（Qwen2.5-Coder 同系列 dense）：

| 模型 | `auto` 主动调用 | `required` 成功 | 95% CI 上界 |
|---|---:|---:|---:|
| 1.5B | **0/200** | 198/200 (99.0%) | 1.8% |
| 3B | **0/200** | 200/200 (100%) | 1.8% |
| 7B | **0/200** | 199/200 (99.5%) | 1.8% |
| 14B | **0/200** | 198/200 (99.0%) | 1.8% |
| 32B | **0/200** | 198/200 (99.0%) | 1.8% |
| **合计** | **0/1000** | **993/1000 (99.3%)** | **0.37%** |

**跨越 21 倍规模，主动调用恒为 0，而能力全程 99–100%。**

这与文献报告的"7B 悬崖"并不矛盾，而是揭示了它的性质：那是**能力悬崖**
（BFCL 等基准测的是"给定该调用时能否调对"），而**主动性维度上不存在悬崖**
——能力在 1.5B 就已接近饱和（99%），主动性在 32B 仍然为零。

**排除了三个替代解释**：
- 不是能力问题 —— `required` 下 993/1000
- 不是注入问题 —— chat template 完整注入 611 字符工具定义（含 `<tools>` 标签与
  `<tool_call>` 格式说明）
- 不是措辞问题 —— 三种 system prompt（"可以" / "必须先验证" / 四步流程 +
  "不要跳过第 2 步"）在 10 题预实验上均为 0

### 第二层：喂回失败反馈也不重试

强制第一轮调用，把**真实的**测试失败结果按 OpenAI 规范回灌，第二轮放开为 `auto`：

| 模型 | 首轮失败数（可修） | 主动再调 |
|---|---:|---:|
| 1.5B | 72 | **0** |
| 3B | 54 | **0** |
| 7B | 44 | **0** |
| 14B | 47 | **0** |
| 32B | 39 | **0** |
| **合计** | **256** | **0**（95% CI 上界 1.17%） |

**256 道模型自己写错、看到了真实报错、工具就在手边的题，主动重试次数为零。**

### 第三层：外部强制驱动多轮，救回率也极低，且 RL 不改变它

评测端由外部强制每轮回灌测试结果（不依赖模型自主发起）。540 题中靠 turn2+
救回的题数，**三个独立 run × 11 个评测点 = 33 次测量**：

```
step      0  15  30  45  60  75  90 105 120 135 150
GRPO/42   8   7   5   7   5   7   8   9   9   8   9
GRPO/1    7   9   6   6   7   6  10   8   9   8   6
RLOO/42   8   7   6   7   7   7   7   5   6   6   8
```

**全部落在 5–10 题（0.9%–1.8%），无一例外，且均无趋势。**

## 2. RL 训练：涨的部分全在初稿

### 2.1 McNemar 配对检验（step 0 → 150）

| run | 指标 | step 0 | step 150 | Δ | p |
|---|---|---:|---:|---:|---:|
| GRPO seed42 | final_pass | 64.8% | 67.5% | +2.8% | 0.064 |
| | turn1_pass | 63.3% | 65.9% | +2.6% | 0.093 |
| | repair_rate | 56.8% | 61.5% | +4.6% | 0.030 \* |
| GRPO seed1 | final_pass | 64.2% | 67.0% | +2.8% | 0.078 |
| | turn1_pass | 62.9% | 65.9% | +3.0% | 0.053 |
| | repair_rate | 57.5% | 61.2% | +3.7% | 0.097 |
| RLOO seed42 | final_pass | 64.6% | 67.2% | +2.6% | 0.077 |
| | turn1_pass | 63.1% | 65.7% | +2.6% | 0.082 |
| | repair_rate | 56.8% | 57.7% | +0.9% | 0.786 |

**`repair_rate` 的变化不构成发现**：三个 run 是 +4.6% / +3.7% / +0.9%，
跨 run 摆动幅度超过效应本身。我们一度把 seed42 那个 p=0.030 当作证据，
**RLOO 推翻了它**——这是本项目最值得记录的一次自我修正。

### 2.2 增益归因

| run | 新通过 | 其中首轮就过 | 占比 |
|---|---:|---:|---:|
| GRPO seed42 | 36 | 34 | **94.4%** |
| GRPO seed1 | 39 | 36 | **92.3%** |
| RLOO seed42 | 34 | 31 | **91.2%** |

**端到端提升的 91–94% 来自初稿质量。** 换训练 seed、换 advantage 估计器，
Δfinal 极差仅 0.2 个百分点。

**方法学注**：`turn-1` 与 `final` 是嵌套关系（通过即停），不可能"turn-1 对而
final 错"，McNemar 的 b 恒为 0，检验退化为单向二项检验，**比跨模型比较灵敏一个
量级**。Step 0 估算的 MDD=6.0 只适用于跨模型比较。

## 3. 机制：失败的题是"完全不会"，不是"差一点"

- 跑满 4 轮仍失败的题，**100% 在第一轮零测试通过**
- 其中 76% 模型**确实改了代码**——不是不改，是改了也不对
- 同一模型在 scripted 探针上（给定几乎正确的解 + 单点注入错误）能修好 **61%**
- 轨迹高度两极：1 轮结束 973 条、4 轮跑满 921 条，**中间状态仅占 4.9%**

### 3.1 排除替代解释：不是 prompt 引导不足

同一 checkpoint、同一批 540 题，只把失败后的追问改为
"请先分析报错的根本原因、你哪一步逻辑出了问题，想清楚再改"：

| 指标 | 默认追问 | 强引导 | p |
|---|---:|---:|---:|
| final_pass | 66.61% | 66.79% | 1.000 |
| **多轮救回** | 2.21% (12 题) | 2.77% (15 题) | **0.505** |

### 3.2 可证伪预测被证实：能力上升则多轮变得有用

| 模型 | turn-1 | final | gap | 救回 | repair |
|---|---:|---:|---:|---:|---:|
| Qwen2.5-1.5B（通用） | 49.1% | 55.4% | 6.3% | 34 | 53.5% |
| Qwen2.5-Coder-1.5B | 56.1% | 59.2% | **3.1%** | 17 | 47.1% |
| Qwen2.5-Coder-7B | 73.8% | 80.6% | **6.8%** | 37 | **82.4%** |

同系列 1.5B → 7B：**gap 翻 2.2 倍、repair +35 个点**。

**但 gap 不是能力的单调函数**：通用 1.5B 的 gap 反高于同规模 Coder 版，
因为它更愿意重试（Coder 版 23.5% 的失败题一字未改，通用版仅 3.3%）。
**多轮的价值由"能力边界"与"重试倾向"共同决定**，单调的只有 repair_rate。

### 3.3 按 bug 类型：符号错好修，逻辑缺失难修

| 好修 | | 难修 | |
|---|---:|---|---:|
| swap_args | 56.9% | drop_guard（漏边界判断） | 33.3% |
| cmp_invert | 52.6% | boolop_flip | 27.3% |
| const_off_by_one | 46.0% | **cmp_boundary（< ↔ <=）** | **20.0%** |

## 4. 一个必须公开的实验缺陷

**训练端的多轮是无效的。** 150 步训练全程 `timing_s/agent_loop/tool_calls/mean
= 0.0`——因为 verl 硬编码走 `tool_choice=auto`，而第一层结论表明模型在 auto 下
从不调用工具。**训练时模型从未收到过真实的工具反馈。**

这意味着 §2 的结论应当读作：**在没有有效多轮信号的 outcome-only RL 下，增益全部
落在初稿**。它不能被解读为"RL 无法教会多轮"——那需要一个多轮信号确实生效的训练。

**为什么不修了重跑**：唯一的修法是全程强制调用（模型不会自主继续，见第二层），
而那恰是评测端一直在做的事，评测端已给出答案（§1 第三层：强制驱动下 150 步训练
前后 8→9 题）。花费与收益不成比例。

**已加的防线**：`CodeTool` 首次执行时落一份凭据文件，`guard_tool_calls.sh` 在训练
启动 15 分钟内检测不到凭据即中止训练。这次故障 4 小时 ¥20 全程零异常信号——语法、
配置加载、schema 注入、奖励曲线、entropy 全部正常，唯一破绽是几千行日志里一个 `0.0`。

## 5. 方法学备注

1. **单点 CI 会让你错过配对检验能检出的效应。** 我们曾用 454 题的非配对单点
   95% CI（±4.6）判定 repair 提升是噪声，配对检验却给出 p=0.030。
   **不发布 per-task 结果，读者连效应存在都看不到。**
2. **单个 run 的 p<0.05 不足以支撑发现。** 见 §2.1 被 RLOO 推翻的那条。
3. **batch=16 下步间奖励方差 ±0.15**，完全淹没模型能力的真实变化。
4. **评测环境影响绝对数值**：同一模型在独立 vLLM 与 verl rollout 下相差 5–10 个点
   （疑似 chat template 差异）。所有对比必须在同一环境内完成。
5. **故障常伪装成正常结果**：`tool_calls/mean=0.0`、缺 `if __name__ == "__main__"`
   的脚本（语法通过、退出码 0、零输出）、`ssh -n` 传出的 0 字节文件——三者都不报错。

## 6. 复现

```bash
python analyze_all.py        # 全部四张表（主检验/稳定性/算法/规模）
```

per-task per-turn 原始数据：`runs/step3/`、`runs/seed1/`、`runs/rloo/`
（step 0–150 每个评测点）、`runs/probe/`（prompt 干预）、`runs/eval7b/`。
**每道题每一轮的代码、观测、通过情况全部保留。**

诊断脚本：`probe_toolcall.py`（工具调用三态判定）、`probe_prompts.py`（措辞变体）、
`probe_multiturn.py`（强制首轮后的重试行为）。

## 7. 局限

- 训练端多轮信号无效（§4），§2 结论的适用范围受此限制
- 单一模型规模做 RL（1.5B）、单数据集、2 个训练 seed + 1 个算法对照
- 未验证有 learned critic 的 PPO——需要独立超参搜索，无法保持"只换算法"的对照
- 规模对比（§3.2）仅 base model 评测，未在 7B 上重跑 RL
- 小模型工具调用失败、GRPO 多轮不稳定等结论已有工作报道，本文不主张首发权
