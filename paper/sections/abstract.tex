Evaluations of LLM agents routinely report tool-call rates taken from the serving stack.
We show this number can be zero while the model emits well-formed calls, and that the
resulting misattribution contaminates both benchmarks and reinforcement learning.

Configuring four model families for function calling on vLLM \emph{following official
documentation}, we find each fails at a different layer, and---critically---the most
consequential failures are silent: DeepSeek-Coder's chat template never injects tools;
Qwen2.5-Coder emits JSON the recommended \texttt{hermes} parser cannot see; Llama-3.1-8B
hallucinates \emph{the task function itself} as a callable tool in 23\% of items;
Mistral-7B repeats its \texttt{[TOOL\_CALLS]} marker and triggers HTTP 400. Apart from a
missing \texttt{--enable-auto-tool-choice}, every failure we found either returns HTTP 200
with an empty \texttt{tool\_calls} array or is indistinguishable from a model that declines
to call tools.

For Qwen2.5-Coder the undercount \textbf{grows monotonically with scale}: across a
21$\times$ range the server parses 0/100 calls at every size, while well-formed calls the
model actually emits rise from 0 to 80/100 at 32B (human-validated, $\kappa=0.936$).
Llama's failure is eliminated by a single \texttt{strict: true} flag ($23\to0$,
$p=0.0001$)---a remedy that three prior single-variable controls failed to identify.

The same mismatch reaches \textbf{RL training}: under function calling a 10-step GRPO run
executes \textbf{zero} tool calls with \texttt{num\_turns} pinned at its minimum, while a
ReAct run matched in model, data, hyper-parameters, seed and prompt strength (though not in
step count) executes 2.05 calls per rollout. The training dashboard shows nothing wrong:
\texttt{critic/rewards/mean} climbs from 0.233 to 0.281 \emph{while the tool-execution count
stays exactly zero}. Because the reward admits direct answers, no trajectory ever rewards
tool use---\textbf{the tool-using branch is unreachable by gradient}.

Installing a dedicated adapter restores the mechanism \emph{at evaluation time}
(parse $0\to84$, multi-turn $0\to37$, rescues $0\to9$). \textbf{In training, opening the
channel is not sufficient}: a 75-step run executing 23{,}676 tool calls leaves multi-turn
rescues flat at 6--8/540, indistinguishable from runs in which none executed---the
bottleneck is not singular. A protocol gap nonetheless remains on one of two admissible
families after conditioning on successful parses. \textbf{Interface problems mask protocol problems;
only after fixing the former does the latter become visible.}
